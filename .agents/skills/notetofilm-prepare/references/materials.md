# 面向视频整理材料

先回答：观众是谁、要理解什么、哪些结论必须讲、需要用什么图解释。把事实、意见、示例和待补充项分开。

## 作品目标卡

完整制作时先写一张，写进 `brief` 或 materials.md 开头。句子越具体，后面的镜头越容易定：

| 项目 | 回答的问题 |
|---|---|
| 来源语境 | 材料原本为什么写、给谁看、按什么标准评判，片子要证明的是什么 |
| 观众 | 谁会看，他们已经知道什么 |
| 核心问题 | 全片最终回答哪一个问题 |
| 起点认识 | 观众开始时可能怎么想 |
| 目标认识 | 看完后能解释什么、作出什么判断 |
| 核心对象 | 用什么贯穿全片（一个物件、一条通知、一个人） |
| 表达条件 | 时长、画幅和使用场合 |
| 内容边界 | 哪些问题留给别的作品 |

“介绍某个流程”只是题目；“解释为什么已经收到通知，柜台却找不到包裹”才是一项表达任务。题目太大、想同时讲背景和个人命运时，回到目标卡，收窄到一个问题和一个可追踪的对象。行业规模这类资料，只有帮助回答核心问题时才放进片子。

## 来源语境

用户发来的常是一篇大文档里的一节：评选材料中的一个案例、汇报里的一段经历、培训手册里的一则故事。只读这一节，容易把它当成独立的小故事来讲。先看整篇目录和相关章节，回答三件事：

- 这份材料原本为什么写：参评、汇报、教学、宣传还是存档。
- 谁会读：评委、同行、新人、客户还是公众。
- 按什么标准评判：文档里的评价维度、打分规则、评语，或材料自带的框架和定性。

这些答案说明片子要证明什么，写进目标卡的“来源语境”，再据此定核心问题和目标认识。材料自带的框架、定性标签不必念进旁白，但它们指明了哪些内容要讲足：评选看重当事人的判断，决定的时刻就要给足时间；技术细节只用来交代处境时，压到能看懂处境为止。

例：用户只发来一份社区服务评选文档里的一个获奖案例。整篇文档开头写着评选看重“发现问题的人怎样决定接手、怎样带动别人、留下了什么做法”，案例后附有评语。片子的主线就跟着这几项走；案例里设备故障的原理只用一两句交代，不展开成图解。

整篇文档里与本片无关的内容（其他人的姓名、成绩、内部数据）不抄进 materials.md。文档没写用途时，把推测出的几种用途和依据列给用户选，不要自己定一个开工。

## 来源与用途

来源记录使用稳定 `source_id`、名称、相对路径或原始链接、页码或段落位置。有用原图同时保留文件和位置，文字提取不能代替图中的流程关系。

按用途标明材料：事实证据支撑讲述，外观参考约束人物和设备，风格参考说明审美方法，现成媒体供选择剪辑。同一文件可以有多个用途，须分别写明。连环画或风格例图可以启发视频语言，只有用户要求时才把其构图当成逐帧约束。

## 区分四类内容

| 类别 | 回答什么 | 怎样使用 |
|---|---|---|
| 事实材料 | 发生了什么 | 保留对象、范围、日期和单位；一个案例只支持这一个案例 |
| 人物观点 | 某人怎样理解这件事 | 带着说话者和语境出现，不单独当成普遍原因的证明 |
| 分析与假设 | 我们怎样连接材料，准备尝试什么 | 写明是分析或假设；没有实际运行结果时，不写效果数字 |
| 示意与比喻 | 帮助识别和理解的画面 | 写明是示意，并说明它和真实信息的对应关系 |

每个重要主张写一小段：准备说什么，依据来自哪里，材料实际支持到什么程度，还缺什么。主动找一个可能推翻当前解释的情况，看是否需要缩小题目或交代范围。

## 采访或第一手材料

材料是采访记录时，优先找能进入镜头的细节：当时在哪里、想完成什么、先做了什么、哪里发生变化、怎样应对、结果如何，再看其判断与感受。整理时保留必要上下文，不把一段有条件的回答剪成绝对判断。用户还能补采访时，把这些问题列给用户；问题里不预先塞答案（例如“是不是系统设计导致大家白跑”），改成请对方展示过程，再追问哪一步与预期不同。

## 写 materials.md

编写 materials.md 时采用“目标卡、主线候选、必讲事实、观点与分析、解释与例子、可用图、具体缺项”结构。可讲事实逐条编号（如 F01、F02），每条注明来源 ID 和位置；后续旁白、屏幕文字和段落卡用编号说明依据。追加材料时沿用已有编号。只保留此次任务实际相关内容；不要把备稿讨论、工具操作过程和版本演变直接放进正式讲解。

遇到多个数字冲突时列出两处内容与来源，不合并成自己猜测的新数字。只整理资料不必强行决定声音和视频时长。研究可以结束的标志：核心问题已有可讲的答案，关键画面有材料或示意方案，尚不明确的地方能用一句话交代。
