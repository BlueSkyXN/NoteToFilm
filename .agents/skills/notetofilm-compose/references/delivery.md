# 最终文件验收与本地审阅

技术检查使用 `ntf inspect FINAL_FILE --decode --audio-check`，按交付要求添加尺寸、帧率、时长和音轨验收参数。可解码、非空音轨和响度合格不能替代内容审阅。

## 按时间看成片

联系表把视频按时间抽帧排成网格，每格标注源时间和镜头 ID；`sheet.json` 列出每帧对应的字幕。用当前客户端读取图片，按下面的顺序看：

1. 全片：`ntf sheet FINAL_FILE --output DIR --timeline TIMELINE --fps 1`，短片可用 2。先只看画面，判断每段的变化能否看出来；再对照字幕与旁白。
2. 剪点：`ntf sheet FINAL_FILE --output DIR --timeline TIMELINE --cuts --fps 8` 查看每个剪点或转场前后。对照转场对：A 镜结束时的状态在 B 镜是否成立，对象的位置、方向和数量是否连续。
3. 关键变化：段落卡写明的关键时点，用 `--start`、`--end` 配合较高帧率复看。改版前后或几个方向之间，用 `ntf compare 旧.mp4 新.mp4 --at … --output DIR` 在同一时刻并排比较；生成画面里的小字用 `--crop` 放大查看。
4. 定位提示：`ntf inspect FINAL_FILE --scan --timeline TIMELINE` 标出冻结、低运动、黑场和静音区间，并给出剪点与镜长（`pace`）。段落卡里有意停留的区间用 `--hold 开始-结束` 声明，落在其中的冻结和低运动区间标为 `intended`，其余逐段判断是不是空等；低运动区间常是一张图上只有字和线在变，人和镜头没动；黑场条目 `has_content` 为 true 时是深色有内容的画面。意外的黑场、静音和断音回到对应镜头处理。
5. 声音：`ntf inspect FINAL_FILE --audio-check --output DIR` 另给倍频程平衡和波形、频谱图；有吸气 → 爆发的段落，用 `--drop 重拍秒数` 量重拍前那半拍是否真的空下来。

每次查看写入新的空目录，旧记录保留，便于对照修改前后。联系表能发现状态回退、对象跳变、字幕遮挡和画面与旁白不符；帧间运动是否平滑、有无微抖，以及声音听感，需要人连续播放确认。没有人看过时，在汇报中写明这几项未检查。

内容检查包含：事件顺序和时态、人物和物件连续性、技术关系、动作是否可读、重复画面的用途、字幕遮挡、准确文字的阅读时间、旁白发音及截断。画面文字单独过一遍：生成画面里的面板编号、条码和伪文字，以及与内容无关的角标、图号、修订号都要去掉；画面上已经写着同一句话的镜头不再叠旁白字幕（该镜 `"subtitles": false`）。声音按 `--scan` 给出的停顿区间复听。`near_silence_seconds` 标出持续极低电平，`digital_silence_seconds` 统计所有声道样本连续为零的时间。发现底声突然中断时，对照原片和混音安排，确需连续环境声的段落可按工具箱“房间底噪”补声。抽几句旁白对照联系表，看画面与旁白所说是否矛盾。分别记录技术检查和内容检查，写明看过的范围和未检查的部分。

## 三种看法与审片记录

- **只看画面**：联系表先不读字幕，人物、地点、贯穿对象和状态变化能否辨认，流程箭头的起止是否清楚，前后图形能否比较。
- **只读旁白**：把正式旁白按顺序读一遍，代词有没有明确对象，开头的问题有没有被回答，假设或方案有没有被说成已经取得的效果。
- **连续看**：不暂停地看完，哪里来不及读，哪里等太久，哪里需要回想上一镜。Agent 不能连续播放时用 `--scan` 的冻结、低运动区间和高帧率连续帧代替，并说明这部分没有人连续看过。
- **手机尺寸**：用 `ntf sheet FINAL_FILE --output DIR --cell-width 360` 按接近手机的尺寸看一遍，小字、标签和字幕在这个尺寸下仍能读清。

节奏显慢时，先把 `--scan` 列出的每段冻结和低运动区间归类：读字、揭晓前的等待，还是只剩口播。再试在观众认出变化的那一刻切走。若会错过手的接触、两行证据的比较或结果揭晓前的期待，就留下足够时间；若只剩画面缓推或口播重述，收短这一拍。配音需要保留时，让例子在这段时间里实际走到下一步。按原速复看改动和相邻的两个剪点。

拿联系表对着旁白逐句看，尤其是第一次说出片名、章节开头和整页切换后的第一句。汇总扫描结果时，直接读取报告里的 `scan.freeze`、`scan.low_motion` 列表和 `scan.pace`。人物、案例片里低运动占比过半、中位镜长六七秒以上时，观众多半会觉得人物是静止的，先看是不是一句话只配了一张图。缺少该字段时回查原报告。扫描标出画面变化很小的时段。转圈或缓推时，也要看观众能否在这句话说到时看见相应的对象。画面还在等，就补上对应内容，或收短这一拍。

人物案例另看主角出现在哪几镜，作决定、调资源和带团队的时刻是否看得见这个人。全片再看版式：连续几镜都是一侧标题一侧照片，或卡片逐条出现时，观众会觉得在翻幻灯片；换景别或主体，或让上一镜的某个元素长成下一镜。

每轮审片写进项目备稿（例如 `work/review-log.md`），格式可以是：

```markdown
## 第 N 轮
技术检查：通过的项和未通过的项
观察：开头 / 节奏与密度 / 内容变化与承接 / 构图与可读 / 内容与数字口径 / 记忆点 / 风格一致 / 声音（不适用的写“不适用”）
最严重的三个问题：
1. [12.4–15.0 秒] s05 通知分支出现后马上切走，读不出先后 → 稳定状态延长到 3 秒
2. …
重做范围：s05、s06
仍未解决（交付时告诉用户）：…
```

请人盲看时，正常播放、不暂停也不解释，问三件事：看到了什么，哪里变了，最后留下什么；再问哪一刻紧、哪一刻拖。记录具体时点，“不高级”这类反馈继续追问是主体不明确、速度不合适，还是画面之间缺少关系。

## 独立审片

动作重复、主体重叠、词读错和伪编号容易在反复自审时漏掉。需要第二个视角，且当前任务允许委派时，可以请一个没参与制作的 Agent 独立审片。

- 给它：全片和剪点联系表、关键时点的连续帧、局部放大图、`--scan` 结果、正式旁白文本，以及设计摘要里的“观众带走”和禁止清单。不给制作过程、代码和你自己的审片记录，免得它沿着你的思路看。
- 让它交回：按严重程度排序的问题清单，每条带时间、看到了什么、它猜的原因；以及它最不确定的三处。
- 它的结论和你自己的审片分开记录；修完再请它看一次，区分“旧问题修好了”和“新发现的问题”。它提出要往片子里加东西时，先转给用户决定。

宿主不能派子 Agent 时跳过这一步。无论有没有独立审片，都不能代替用户自己看片。

## 双遍响度校准

使用 `ntf normalize`。它复用现有 FFmpeg/ffprobe，复制视频码流，只重编码第一条音轨为 AAC，生成新的 MP4。输入应是已合成的单视频、单音轨成片；其他轨道不会自动保留。

指定原成片、新输出及响度目标：

```bash
ntf normalize FILM.mp4 --output FILM-final.mp4 \
  --lufs -17 --true-peak -2 --lra 11 --report loudness.json
```

命令先测量，再带测量参数执行 `loudnorm`，最后复测编码后的文件。报告区分目标值和实测值，AAC 编码后仍可能存在小偏差；按实际交付容差判断。静音或缺少音轨时明确报错；源文件和已有输出不覆盖。已满足响度要求时无需重复处理。

## 可拖动的审阅入口

定制动画和独立混音合成后，从 `ntf status PROJECT` 的 `renders` 找到采用的版本。该版的 `renders/<id>/inputs.json` 保存了当次分镜、采用关系和已解析的清单，`timeline.json` 给出镜头的实际时间。交付可续改项目时，让接手人能由镜号找到对应的页面、绘制函数或素材文件；共享一段连续动画的镜头同时写明各自的起止位置。

最终成片如果经过响度或其他后处理，明确指定该文件，避免自动选到较早的 render：

```bash
ntf preview PROJECT --video FILM-final.mp4 --timeline TIMELINE.json --output REVIEW_DIR
ntf serve --directory REVIEW_DIR --port 0
```

`TIMELINE.json` 使用本次合成返回的时间表；响度处理保留画面时间，若另行改变剪辑则使用对应的新时间表。命令检查总时长、镜头 ID 和窗口；使用时间表的真实顺序生成审阅卡片。

使用 `ntf serve` 返回的本地地址。服务支持 GET/HEAD 和单段 HTTP byte range，只监听 `127.0.0.1`，不列目录，不跟随越过根目录的符号链接。停止时向进程发送 Ctrl-C。`preview` 返回的 `serve_argv` 也可直接执行。

只服务 `preview` 导出的独立目录，原始项目的 state、work、连接配置和任务快照不进入审阅交付。打开页面后检查视频能播放、能拖到中段和结尾；审阅页序号、镜头总数、章节与正式分镜当前顺序一致。

最终返回 MP4、审阅入口和必要字幕，说明文字、声音来源与仍需确认的具体内容。`normalize` 产生的新文件通过 `preview --video --timeline` 明确采用，保留原成片记录。
