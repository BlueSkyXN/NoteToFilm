# 终端字符（terminal-ascii）

> 一切由等宽字符组成：命令行在打字、字符图形在流动、光标在闪，冷静又极客。
> 参照（只学语法）：命令行界面、ASCII art、demoscene 的文本模式作品。不照搬具体作品。

## 本质 / 不是什么
- 本质：**字符网格就是像素**；图形用字符密度（` .:-=+*#%@`）表达明暗；文本真的按字符逐个出现；光标是节奏器。
- 不是：绿色字符雨的陈词滥调；也不是满屏无意义的滚动代码。

## 辨识信号：每支片子挑 2–3 个
| 信号 | 长什么样 | 适合的主题 |
|---|---|---|
| 逐字打出的命令 | 提示符后的字一个个出现，回车后输出 | 工具、安装、一条命令 |
| 字符明暗图 | 用字符密度或块字符画出的图形、名称 | 落版、图形 |
| 光标 | 闪烁的块光标或下划线光标 | 节奏、等待 |
| 字符进度条 | `[#####     ] 50%` 这类进度 | 构建、下载 |
| 日志滚动 | 带时间戳的日志一行行往上冒 | 运行、监控 |
| TUI 面板 | 用制表符画的边框、分栏、菜单 | 仪表盘、管理工具 |
| diff 着色 | 红色删除行、绿色新增行 | 代码变更、和上游的差异 |
| 目录树 | ├── 和 └── 组成的树状结构 | 项目结构、入口清单 |
| 表格输出 | 对齐的列、表头分隔线 | 数据、对比 |
| 磷光屏 | 琥珀色或绿色单色屏，带一点余辉 | 复古、硬件 |
| 字符重组 | 满屏字符飞散后拼成另一个形状（窗口、手机、名称） | 一个命令的几种形态 |

规则：
- 每支挑 2–3 个，至少一个不在下面「最俗的版本」里。
- 信号从主题里选，不按顺序全上。
- 命令、参数和输出要真实：取自产品文档或真实运行，问用户要，不编。

## 这个风格最俗的版本
- 画面：黑底绿字、字符雨、满屏滚动的假代码、结尾「ACCESS GRANTED」。
- 声音：机械键盘声、低频嗡鸣、电子哔声。
- 设计备稿的视觉语言一栏写明这支片子翻掉了哪几条，或者为什么刻意保留。保留时，把力气花在构图、镜头、节奏或一个意外的记忆点上。

## 适配
- 用途：开发者产品的宣传短片、片头、名称演绎、作品集的一段。
- 内容：CLI 工具、AI agent、开源项目、安全、数据。

## 材质与渲染
- 字符逐格对齐，字号统一（可以有一个更大的标题网格）。
- 字符图形：把图形或名称先画到离屏画布，按格子采样亮度映射到字符或块；名称用细格像素块（例如 9×16 设计像素一格），太粗的格子读不出字母。
- 光标：块状光标，按约 0.5 秒的周期闪烁（用 t 计算，不用计时器）。
- 扫描线、暗角和轻微闪烁放在最上层，幅度很小。

## 配色
下面的色值是示例，看思路，不要原样照抄。
- 深灰 `#181D24` / 浅灰 `#D7DAE0` / 绿 `#4ADE80` / 红 `#F87171` / 强调（品牌色）
- 暖黑 `#1C1B19` / 米白 `#E8E3D3` / 橙 `#FF8C3B`（复古琥珀屏）
- 浅色终端：`#F6F6F2` / `#1E1E1E` / 蓝 `#2F6FEB`
- 规则：语义配色（成功绿、警告黄、错误红），不用于装饰。
- 推导：底色可以是深灰、暖黑、浅色终端或品牌色的深版，强调色从品牌来。纯黑底配少量文字的帧会被扫描判为黑场（条目里 `has_content` 为 true），看原帧确认；底色略提亮到深灰也更耐看。

## 字体
JetBrains Mono、IBM Plex Mono、Fira Code、Space Mono（OFL）。全片只用一种等宽字体；中文落在等宽字体里会用回退字体，宽度不一，对齐的列里少放中文。

## 运动
- 打字：每字符 20–45 毫秒，标点后稍停；命令回车后输出一次性或分块出现。
- 字符图形的变化：每帧重新采样，图形本身可以平滑变化（字符是离散的，看起来会自然地「颗粒化」）。
- 字符重组：每个字符从旧位置飞到新位置，飞行中随机换字，落定后才显示目标字符；时长 0.35–0.6 秒，错峰 0.2–0.3 秒。
- 滚动：整行向上跳，不做平滑滚动（终端就是这样的）。

## 画面怎么活
- 光标闪；日志在后台一行行往上冒；一个字符进度条在走。
- 字符图形里留一小块区域持续重采样流动，其余字符不动，眼睛才有落点。

## 镜头语法
| 镜头运动 | 表达什么 | 适合哪类内容 |
|---|---|---|
| 固定终端窗口 | 真实的操作 | 命令演示 |
| 推近到一个字符，它变成下一个画面 | 进入 | 转场 |
| 拉远，一个终端变成许多终端的阵列 | 规模、并行 | agent、分布式 |

## 声音
键盘声（`click` 或底层 `noise` 做的短敲击，音高随序号变、种子固定）、回车声、低沉的持续音、少量 `blip`。无口播时用 `ntf score`：无拍（打字的节奏就是节奏）或机械的八分、十六分音符低音脉冲；一个和弦、持续低音；拟音主导，底下铺 `ambience(kind='room')`。删除一行用 `glitch` 加下行 `blip`。

## 原生手法
- 一行命令运行后，字符图形从输出里生长出来：适合「一条命令完成一件事」。
- 字符重组：同一堆字符依次拼成桌面窗口、浏览器、终端：适合「一个命令，几种形态」。
- diff 红行逐行被删掉、绿行补上：适合「和上游比去掉了什么、多了什么」，行文取自变更记录原文。
- 字符网格整体变成名称的明暗图：适合结尾落版。

## 变化空间
- 结构：一次安装到成功的过程；一个 agent 的一次任务；一个 bug 从报错到修好；一份差异清单。
- 开场：一个闪烁的光标；`$` 提示符后的第一个字。
- 结尾：最后一行输出后，字符网格组成名称。

## 坑
- 编造命令、参数和输出：只用真实存在的命令；输出没有真实来源时，用色条或字符图形代替。
- 绿字符雨等陈词滥调。
- 字号太小，手机上看不清：主要的命令行至少 28px（1080p）。
- 字符重组途中的乱码会让文字检查刷屏：用骨架 `kit.js` 的 `decorative()` 包住飞行中的字符。

## 在 NoteToFilm 中制作

- **路线**：代码动画为主；真实运行的终端录屏可按现有素材剪辑处理。
- **图片生成、视频生成**：不用于终端内容。
- **`ntf motion`**：真实终端截图的推近和逐行显露。
- **代码动画**：Canvas 2D 固定字符网格；逐字打出按 t 计算已显示的字符数；字符图形在 `READY` 之前一次采样；扫描线和暗角放最上层。
- **准确文字**：命令、参数、路径和变更项取自产品文档或仓库记录。
