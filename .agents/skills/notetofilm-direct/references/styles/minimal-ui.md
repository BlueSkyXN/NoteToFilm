# 极简界面（minimal-ui）

> 干净的舞台上，界面元素在变形、点击、拖拽，每一个变化都有弹簧手感。
> 参照（只学语法）：精致的界面动效、Apple / Linear / Vercel 一类的产品动效。不照搬具体品牌的界面和图标。

## 本质 / 不是什么
- 本质：**界面本身是主角**，在一个干净、安静的舞台上被真实地使用：一个元素连续变成下一个状态，光标真的在点、在拖，尺寸和圆角的变化都有弹簧手感。舞台可以是浅色，也可以是品牌色或深色，只要安静、不抢界面。
- 不是：赛博 HUD、深色加霓虹、拟物化；也不是把截图平移一下的幻灯片。

## 辨识信号：每支片子挑 2–3 个
| 信号 | 长什么样 | 适合的主题 |
|---|---|---|
| 形变链 | 一个按钮连续变成加载、对勾、卡片……不切镜头 | 功能串联、流程 |
| 光标操作 | 光标移动、悬停、按下、拖拽，带真实的加减速 | 交互、教程 |
| 浮起的卡片 | 白卡片带柔和投影，从舞台上浮起 | 产品亮相 |
| 前后沿拉伸 | 指示条移动时前沿快、后沿慢，被拉长 | 切换、导航 |
| 真实截图里的推近 | 镜头推到真实产品界面的某个按钮上 | 产品宣传 |
| 系统控件 | 开关、滑块、分段控件、键盘快捷键提示 | 工具类产品 |
| 命令面板 / 搜索 | 一个输入框里逐字出现查询，结果列表弹出 | 效率工具、开发者 |
| 通知和 toast | 从角落滑入的提示，几秒后收回 | 状态、提醒 |
| 深浅色切换 | 同一个界面在亮色和暗色之间翻转 | 主题、设置 |
| 手机或窗口外框 | 界面装在一个极简的设备或窗口框里 | 多端产品 |
| 分屏复制 | 同一个动作在几个入口的格子里踩同一拍发生 | 多入口、多端 |

规则：
- 每支挑 2–3 个，至少一个不在下面「最俗的版本」里。
- 信号从主题里选，不按顺序全上。
- 真实产品优先用真实截图或真实界面录制，信号挑的是怎么展示它。

## 这个风格最俗的版本
- 画面：浅灰底 + 正中一张白卡片 + 蓝色强调色，按钮 → 加载圈 → 对勾，结尾拉远出 logo。
- 声音：柔和的 click、pop 加一条干净的电子拨弦旋律。
- 设计备稿的视觉语言一栏写明这支片子翻掉了哪几条，或者为什么刻意保留（比如用户要的就是经典版）。保留时，把力气花在构图、镜头、节奏或一个意外的记忆点上。

## 适配
- 用途：界面动效演示、产品宣传短片、功能介绍、开源项目宣传。
- 内容：App、SaaS、开发者工具、AI 产品、设计系统。

## 材质与渲染
- 圆角卡片（12–28px）、1.5–3px 细描边或无描边、柔和投影，只给浮起的那一层。
- 图标线宽统一（1.75–2px），不用 emoji。
- 光标：简单的矢量箭头，按下时缩到 0.88 并出现扩散圆环。
- 画出来的界面里，正文用色条代替，不写看起来像字的伪文字；需要读的只有按钮名、入口名、状态这类准确文字。
- 可以有一层非常淡的颗粒（`--grain 2–3`）。

## 配色
下面的色值是示例，看思路，不要原样照抄。
- 背景 `#EFEDE8` / 卡片 `#FFFFFF` / 墨 `#111111` / 灰 `#8A8780` / 强调 `#3B5BFF`
- 背景 `#F5F4F1` / 卡片 `#FFFFFF` / 墨 `#0F0F10` / 强调（品牌色）
- 规则：强调色只给当前被操作的那个元素，或者状态成功的时刻。
- 推导：舞台色（暖灰、冷灰、品牌色的极浅版、深色都可以）+ 卡片 + 墨 + 一个强调色。强调色优先用品牌色；蓝色是最常见的那个。

## 字体
一款干净的界面字体加一款等宽字体：Geist、Instrument Sans、Manrope、Inter Tight；等宽用 Geist Mono 或 JetBrains Mono。中文用思源黑体 Medium / Bold。

## 运动
- 弹簧档位：指示条、开关 `{3.6, 0.8}`；容器 `{2.4, 0.75}`；大标题 `{1.6, 0.95}`。最多带一点回弹。
- 前沿和后沿分开（compose 代码动画写法第 2 节）：移动中的条被拉长。
- 容器里的内容换状态时，旧内容先模糊淡出 0.1 秒，新内容延后 0.08 秒进场。
- 拖拽：按住时数值由光标位置决定，松手后从当前位置弹回吸附值。

## 画面怎么活
- 光标的待机：小幅漂移或停在按钮上轻轻悬停；后台的进度条、数值继续走；一个状态点（在线、录制中）缓慢脉冲。
- 界面以外不加装饰性动效，活的东西都应该是界面本来会有的状态。

## 镜头语法
| 镜头运动 | 表达什么 | 适合哪类内容 |
|---|---|---|
| 跟随当前状态缩放 | 聚焦当前操作 | 每一个界面状态 |
| 轻微倾斜后回正 | 状态切换的能量 | 形变的瞬间 |
| 拉远到完整页面 | 全貌、上下文 | 结尾、总结 |
| 推进一个按钮 | 进入下一个功能 | 段落切换 |

## 声音
界面音效在前：`click`、`tick`、`pop`、`swipe`，成功时一声 `bell` 或 `mallet`。无口播时用 `ntf score` 写配乐，音乐退后（总线 gain 0.3–0.4）：`pluck` 五声音阶琶音、轻底鼓、软拍手；`mallet(material='marimba' 或 'kalimba')` 可以替代拨弦。直拍或轻 swing，大调五声、Lydian；一问一答（操作 → 界面回应）很合适。干、短，不开侧链或开得很轻。有旁白时只留界面音效和很轻的底声。

## 原生手法
- 形变链：按钮 → 加载 → 对勾 → 卡片……一镜到底。适合功能串联。
- 拖过头被拉长：适合滑块、音量、进度。
- 开关的圆点变成下一个组件的指示条：适合流程衔接。
- 分屏复制：1 → 2 → 3 → 6 格，几个入口踩同一拍做同一件事。适合“同一个能力，多个入口”；画面会被读成状态同步，材料不支持时在字幕或画面上把范围说清。

## 变化空间
- 结构：一个用户完成一件事的完整路径；一个组件的 10 种状态；先减法（划掉去掉的东西）再亮出干净的界面。
- 开场：一个按钮被光标点下的那一帧；空白画面里一根光标进入；界面上从第 0 帧就在弹出东西。
- 结尾：所有状态收回成最初的按钮（循环）；拉远露出完整产品界面和名称。

## 坑
- 被缩放的元素加了 `will-change`，文字会糊。
- 新旧文字叠在一起。
- 投影太重、描边太粗，会变廉价。
- 用画出来的假界面冒充用户的真实产品：要展示具体功能时用真实截图或真实界面录制；画出来的界面只表达结构和状态。
- 界面里写伪文字和编出来的数字。

## 在 NoteToFilm 中制作

- **路线**：界面、状态与流程用代码动画；真实产品画面来自用户提供的截图或录屏，按现有素材剪辑处理。
- **图片生成**：只用于舞台背景、设备或使用场景，不生成界面本身（生成的界面会带伪文字）。
- **视频生成**：只用于真实使用场景的情境镜头。
- **`ntf motion`**：真实截图的推近、遮罩显露和标注。
- **代码动画**：DOM / SVG 或 Canvas，骨架 `kit.js` 写设计坐标；形变链用 `springTo` 连续改目标，`--subframes 4` 处理快速形变，细线小字加 `--dpr 2`。
- **准确文字**：入口名、按钮名、命令和地址取自产品文档或界面原文。
