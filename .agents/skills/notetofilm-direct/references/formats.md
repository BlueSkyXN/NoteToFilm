# 片型配方：观众在做什么，片子按什么推进

片型按观众的主要观看任务区分：跟随一个行动、观察一个处境、理解一个机制、比较几个对象，或者建立一种感受。先选一个主片型定主线，需要时借另一个片型的段落。常见组合：机制解释作主体，用反差开头，让一个人的处境贯穿全片。片型、画风和制作路线分别选择，同一片型可以配任何画风。

先看总表，只读选中的一两节。结构是起点，段落内容从材料来，时长按实际旁白和阅读定。手法编号见 [观察方式](techniques/camera.md)、[信息变化](techniques/info-motion.md) 和 [衔接方式](techniques/transitions.md)；开头的写法见 [旁白与画面文字](script.md)。

| 片型 | 观众在做什么 | 推进结构 | 常见长度 |
|---|---|---|---|
| 反差解题与机制解释 | 理解一个原本不清楚的关系 | 异常 → 对象 → 条件与关系 → 中间原因 → 回到结果 | 1–5 分钟 |
| 案例故事 | 跟随一次选择和行动 | 处境 → 阻碍 → 选择 → 行动 → 变化与证据 | 45 秒–3 分钟 |
| 人物经历 | 认识一个人为什么这样做 | 具体经历 → 关键选择 → 行动与影响 → 人物判断 | 1–5 分钟 |
| 事件调查与节点回望 | 弄清发生了什么、怎样走到今天 | 事件 → 材料与说法 → 细看对象 → 不同解释 → 有范围的判断 | 1–8 分钟 |
| 方案对照与观点论证 | 比较差异，判断是否成立 | 共同任务 → 相同条件 → 差异 → 代价 → 适用条件 | 45 秒–4 分钟 |
| 产品演示与操作教程 | 看清一项操作怎样完成 | 任务 → 条件 → 关键操作 → 反馈与结果 → 常见错误 | 20 秒–3 分钟 |
| 产品发布与开源项目宣传 | 记住它是什么、和同类差在哪 | 看得见的差别 → 名称 → 两三个凭据 → 落版 | 15–60 秒 |
| 方法与实践分享 | 理解一套做法和背后的取舍 | 具体的痛点 → 一句话做法 → 跟着一件事走完 → 全景 → 两三个取舍各配一个例子 → 这套做法怎么来的 → 回到开头 | 2–5 分钟 |
| 数据爆点 | 被一个数字或一组对比说服 | 口径 → 变化 → 落定 → 一句解释 → 来源 | 6–30 秒 |
| 现场观察 | 进入一个处境，等待变化 | 进入处境 → 劳动或等待 → 变化 → 反应与余波 | 45 秒–3 分钟 |
| 情绪与品牌短片 | 建立一种感受 | 母题 → 变奏 → 转折 → 带着新含义回扣 | 15–90 秒 |
| 片头、落版与金句 | 记住一个名字或一句话 | 预备 → 形成 → 定格 | 4–15 秒 |

信息流里的短版本（15–60 秒）从任一片型压缩：开头几秒给出对象、异常或观看承诺，正文只兑现这一个承诺，结尾回答它。观察和讲解仍按各自需要的时间走，短片也可以有停顿。

## 反差解题与机制解释

- **结构**：先给一个看得见的反差（看起来变好了，结果却更难；通知到了，东西却拿不到），再认识对象，建立条件与关系，补上中间那一步原因，最后回到开头的现象重新判断。观众带走的是一条因果链。
- **开头**：具体反差、一个细节或结果前置。
- **手法**：M09 总览进入局部，M04 保留与增补，M06 同位对照，M02 路径绘出；T05 共享对象从现场进入图解，再回到现场。
- **画面分工**：现场或人物情境承担“遇到了什么”，可编辑图解承担机理，同一对象从现场贯穿到图解再回现场。机理需要毫米级关系时交给图解，生成视频承担现场、动作和结果。
- **坑**：每句旁白换一张不相连的配图；术语先于对象出现；图解只在运动瞬间看得懂；连续几页图解不回到现场，片子像讲稿；把先后发生画成因果。

## 案例故事

用于管理案例、项目复盘和一次应对的经过。

- **结构**：处境（已有判断和未解决的问题同时存在）→ 阻碍 → 选择（谁在什么条件下决定）→ 行动（资源从准备到到位，几项工作同时推进）→ 变化与证据（短期帮助和长期改变分开写）。
- **三条线交替**：人物负责立场、判断和协同；物件负责让困难与行动可见；方法负责说明这次应对怎样影响后续工作。
- **手法**：M04 让两个事实同框（例如“产品达标”和“客户仍不能用”），C01 固定镜头看完一个完整动作，M08 并行展开或 T14 交叉剪辑表现同时推进，M07 记录汇表表现方法形成。
- **画面分工**：选择和行动用人物情境，结构原因用图解，结果回到同一对象的完成状态。
- **坑**：管理者被拍成做所有技术操作的人；虚构争吵、倒计时、损失数字或客户表扬；正片里出现备稿讨论和分析框架；单个动作（例如放下手机）被当作行动已完成，后面没有备料、到位和处理来接住。

## 人物经历

- **结构**：从一次具体经历进入（当时在哪里、要完成什么、卡在哪、先做了什么、谁受影响），再到关键选择、行动与影响，最后才是人物的判断。
- **素材**：本人原话或录音、能进入镜头的物件和档案、相关行动的画面。没有本人录音时用普通旁白，不模仿真人声线。
- **手法**：T07 声音延续让讲述延伸到相关材料，T03 视线把注意引到下一个对象；关键选择后留一次反应。
- **坑**：只有履历、头像和荣誉清单；把别处的表情接到一句话后，暗示当事人的态度；第一人称改编稿当作本人逐字原话。

## 事件调查与节点回望

- **结构**：调查按“发生了什么 → 已有说法与材料 → 细看对象 → 几种解释怎样对应材料 → 有范围的判断”；回望按“当下状态 → 关键节点 → 各节点的意义 → 下一阶段”。
- **材料**：照片、文件、地图、时间线、访谈记忆，各自保留来源、日期和语境。档案缺口保留为缺口。
- **手法**：M01 遮罩显露和 M09 资料展开（整体 → 相关局部 → 回到全貌），C09 数字裁切进入局部，T13 时间省略并交代时间，T11 淡黑分隔较大的时间跳转。
- **坑**：动画补出的细节被说成证据；不同地点、不同时间的影像接成同一因果现场；裁掉会改变含义的前提；年份、名称未核实。

## 方案对照与观点论证

- **结构**：对照按“共同任务 → 相同条件 → 差异 → 各自的优势与代价 → 适用条件”；观点论证按“判断 → 证据与比较 → 推导 → 适用条件”。
- **手法**：M06 同位对照（固定尺度和基准，让差异成为唯一变化），M05 原位替换比较同一位置的前后条件，M12 数据先口径后趋势，M16 划改表示纠正。
- **坑**：用不同尺度、光线和镜头夸大优劣；把相关性或个例扩成普遍结论；比较维度前后不一致。

## 产品演示与操作教程

- **结构**：先说明要完成什么、初始状态是什么，再给必要条件、关键操作和反馈；操作完成后留时间读结果。有比较时保证同一任务、同一视角、同一条件。
- **手法**：C01 固定镜头或明确的细节镜头看触点，M03 局部强调；录屏按“移到目标 → 操作 → 显示结果”调度光标。
- **素材**：真实界面、录屏、产品照片或可控模型优先。按钮位置、接口和文字决定理解时，生成画面只能作情境。
- **坑**：功能清单代替使用任务；同时滚动、缩放、打字和解释；关键触点处绕镜。

## 产品发布与开源项目宣传

- **结构**：先给一个看得见的差别（去掉了什么、多了什么、能在哪些地方用），再亮出名称，用两三个凭据撑住，落版写名称和一句话定位；要引导安装时再加一个短入口（项目名、短地址或一条命令），整段安装步骤不进片子。无口播时按小节排，见 compose 代码动画手法库的时长模板。可选的讲法：减法（逐项划掉去掉的东西）、一镜到底形变链（同一个窗口变成几种入口）、台账或小票（逐行打出变更记录）、分叉线（沿提交历史分出分支，节点上掉落或长出功能）、分屏同步（几个入口踩同一拍做同一件事）。
- **素材**：优先用项目里结构化的真实记录：变更台账、发布记录、提交历史、PR 统计、配置模板的名称。数字写明截至哪个提交或日期。本地仓库可能落后远端，用平台 CLI（如 `gh api`）只读核对。界面能跑起来时，录真实界面比画出来的界面可信；录制前确认画面里没有密钥和私人路径。
- **手法**：M05 原位替换比较前后状态，M14 节点生长与退出，M16 划改；记忆点从 compose 代码动画手法库的签名时刻菜单里选一个和卖点含义对得上的。
- **坑**：逐条念功能清单；数字没有出处；比喻带出材料不支持的说法（几个入口踩同一拍会被读成共享同一个会话，合计金额写成 0 会被读成完全免费）；直接排进画面的源数据原文带出还没决定能否出现的名称；分支项目沿用上游图标前没查来源和授权。

## 方法与实践分享

给同行或别的团队讲“我们怎么做、为什么这样做”：一套开发流程、一组 Skill、一种协作方式。观众要带走的是做法和取舍，记住名称是次要的。

- **结构**：开头放一个观众经历过的具体痛点（一步一停、交接丢上下文），一句话说出这套做法换了什么分工；跟着一件真实的事把主流程走一遍，再拉远成全景，让观众看到各部分的关系。之后讲两三个取舍，每个配一个例子：同一套方法怎样按问题大小走不同深度，需求中途变了怎么办，哪些事刻意不做。最后讲这套做法怎么来的（先厘清概念、对照了哪些公开做法、经过几轮评审），结尾回到开头的痛点。
- **素材**：规则和方法文件的原句、设计草案的版本记录、评审意见；作者在讨论里反复强调的取舍，见 prepare 的“介绍软件项目或一套做法”。还没实测效果时只讲做法，不讲提速和成功率。
- **手法**：一张贯穿全片的结构图（线路图、流程图、地图）当舞台，前半走一遍，后半在同一张图上点亮、连线、分叉来讲取舍；“怎么来的”可以换成整页，讲完再回到开头的对象。M14 节点生长与退出，M16 划改，T04 图形匹配。
- **坑**：只读 README 就开工，把需要输入命令的环节讲成自动发生；条件、范围这类限定词比原文说窄；逐条念功能清单，取舍一个也没讲；片中出现安装步骤、开发状态和待办；把讨论记录里的说法当成已发布的事实。

## 数据爆点

- **结构**：铺垫（问题或对比的一方）→ 口径（单位、时间范围）→ 数字滚动或图形长出 → 落定后一句解释，停留约 2.5 秒以上 → 来源。
- **手法**：M12；画面规则见风格库的数据动态。数字只来自材料，事实编号写进备稿。
- **坑**：截断坐标轴不说明；“涨了 9 倍”和“涨到原来的 9 倍”混用；展开后计数从 0 重来。

## 现场观察

- **结构**：进入处境，保留完整的小动作、等待和没有事件的时间；变化出现时跟随；结束后留反应与余波。
- **手法**：C01 固定镜头让事情自己发生，C06 跟拍陪伴一个过程，T08 环境声把几个镜头接成一段，T09 只插与等待有关的细节。
- **坑**：给每个停顿配强音效；为凑景别要求重演情绪；用音乐替人物宣布想法；因为“没增加信息”删掉本来构成处境的时间。

## 情绪与品牌短片

- **结构**：从一个视觉母题（手、门、光线、工具、重复动作）建立气质，让尺度、速度、亮度或密度变化，放一个不符合前面规律的转折，最后回到最初的对象，带上新含义。
- **手法**：T04 图形匹配，T08 声音桥，T13 省略，C04/C05 推拉。音乐可以主导节奏；插进来的解释段仍按阅读和动作留时间。
- **坑**：多种画风同时抢注意；每个镜头同一种慢动作；突然插入正文没支撑的宏大口号；把“推近表示感动、摇晃表示真实、快切表示震撼”当成固定规则。

## 片头、落版与金句

- **结构**：预备（暗示的元素）→ 爆发或形成 → 定格。落版停留 1.5 秒以上。金句按“一拍一个词”或“一小节一句”排，整句出完后停到读完。
- **素材**：Logo 用真实文件，拿不到就问；金句文字来自定稿。
- **做法**：通常用代码动画，写法见 compose 的代码动画手法库。
- **坑**：定格太短；词太多、停留太短；Logo 比例或颜色走样。

## 写进设计备稿

在设计摘要里写主片型、借用的片型段落及理由。章节表按所选结构列出每章“观众要理解什么”；段落卡写用到的手法编号和这一处的目的。材料撑不起所选结构的某一步（例如没有结果证据）时，改结构或在备稿列为缺口，不补造。
