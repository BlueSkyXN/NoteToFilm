# UniAPI / New API 的 Seedance 通道

使用 New API 统一视频接口时配置 `newapi-video` 适配器。`ark-video` 是原生 content-generation 协议；仅更换地址不能将它变成统一视频协议。

模型、连接地址和认证引用由实际路由配置决定。

默认相对路径为 POST `videos`、GET `videos/{id}` 和 GET `videos/{id}/content`；与配置的基址组合，路径可由连接或路由覆盖。提交顶层为 model、prompt、seconds；分辨率、比例、声音开关、参考素材放在 metadata，图片在 metadata.content 中使用 image_url 和明确角色。进行中状态为 queued / in_progress，完成为 completed。

能力分四层核对：供应商参数范围、网关接受的请求、本地适配器已实现的字段、当前路由的实测结果。模型清单和配置声明不能替代后两层；更换网关版本、模型或账号后保留原证据范围。

时长、分辨率与参考图数量按实际服务和路由配置核对。当前统一适配器实现图片参考与基础视频参数，参考视频、参考音频、视频编辑/延长、返回尾帧和 2.5 专用参数尚未接入；不能仅修改能力文件便宣称已实现。

先用 routes 阅读实际配置；protocol 或公司路径未确定时保留计划并说明缺项，不猜默认请求。已明确要求的通道未接通，不自动换成另一条。

单项文生视频请求采用扁平 JSON：

```json
{"kind":"video","route":"<视频路由ID>","mode":"text_to_video","prompt":"<镜头内容与动作要求>","parameters":{"duration_seconds":4,"resolution":"720p","aspect_ratio":"16:9","generate_audio":false},"selection_slot":"s02.video"}
```

其他输入形式见 [模式与输入](../modes.md)。请求示例说明结构，当前路由可用性按配置、实现和实测范围核对。

每条新素材都须探测实际时长、尺寸和音轨。具体请求的失败不能外推整个模式不可用；当前路由的可用性以其配置和实际结果为准。

声音开关与文字要求分开处理。原生声音是否可用需单独核对；模型生成的画面字符、后期旁白字幕和后期关键词是不同来源。有可读性要求的文字优先保留准确排版版本。

对参考输入或输出的拒绝保留任务与错误记录。已指定图生模式时，调整到文生需要明确制作选择，不能把文生成功记作图生成功。
