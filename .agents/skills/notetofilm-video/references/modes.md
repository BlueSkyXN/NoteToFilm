# 视频模式与输入职责

从导演方案确定参考用途，再映射到实际通道支持的输入模式。这里说明项目请求字段；供应商 HTTP 形状、时长和数量上限在对应 provider 资料与配置中核对。

| mode | 项目输入 | 约束的内容 |
|---|---|---|
| `text_to_video` | `prompt` 与 `parameters` | 事件、审美和必要边界，构图及动作由提示要求决定 |
| `image_to_video` | 独立 `start_frame` | 以指定画面作为开始状态 |
| `reference_to_video` | 有序 `references` | 明确各图用于人物、设备、空间或外观；不自动当连续时间点 |
| `first_last_to_video` | `start_frame` 与 `end_frame` | 指定开始和结束状态，中间动作仍需检查 |

实际可调用取决于路由声明、适配器实现和该组合的在线证据。参考视频、参考音频、编辑或延长等模式没有接入时，不能只改配置便视为可用。

每条参考先导入项目，保留素材身份、顺序和用途。纯文生无需补造参考图；用户指定图生时保留其模式，改变路线需在制作选择中明确。

提示词承接导演给出的事件变化、事实边界与自由度。只有要求从指定画面开始时才使用首帧；主体出框时针对关键对象补可见性要求，不自动锁定所有机位。代表短段先检查动作、身份、接触和状态，再扩展其余镜头。

原生声音开关与最终音轨策略分别决定。包含人声的原轨不能直接称为独立环境音；准确字幕和关键词按后期方案处理。当前通道的原生声音是否实测可用，在 provider 资料中单独记录。
