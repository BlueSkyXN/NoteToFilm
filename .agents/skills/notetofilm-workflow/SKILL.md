# 本地视频工作流

## 开始

1. 先读 [本机入口](references/runtime.md) 和 [命令](references/commands.md)。确定本次目标、项目位置、结束阶段及指定镜头。
2. 没有项目时执行 `ntf init PROJECT --title TITLE`。已有项目先执行 `ntf status PROJECT`，读取正式文件；不要从旧对话重建已经存在的分镜。
3. 需要写入内容时读 [项目格式](references/project-format.md)。根据当前输入按 [阶段路由](references/routing.md) 读取相应已安装 Skill。通过客户端提供的位置或安装后本机入口的清单定位，不拼接同胞目录。

## 推进

4. 材料不足时先 prepare；需要确定叙事、玩法、风格或分镜时进入 direct，由它选择制作路线。已有确定方案时直接进入所需媒体阶段。workflow 管理阶段、状态与依赖，设计方法集中在 direct 中按需读取。
5. 先确定声音与文字由谁制作：模型原生声音、独立旁白或混音，字幕与画面关键词分别安排。将选择落实到视频参数和合成策略，分别记录原生声音能力与本次是否采用。
6. 需要探索完整成片时，先用候选结构、方向画面和草图粗剪验证，再做代表段和全片。方向画面优先用已有素材、草图或代码动画静帧。有该阶段试图授权时，可按约定的次数、费用和通道生成少量样图。方向需要用户选择时，带着预览请用户决定；用户已定方向或已委托创意选择时，记录决定和理由后继续。具体做法在 direct 的“从便宜到贵”。
7. 按 [依赖与修改](references/dependencies.md) 选择制作顺序。分镜驱动的制作在正式分镜保存后执行 `ntf plan PROJECT`；特殊依赖使用 `--file FILE`。探索方向时可先用独立 `generate` 取得候选，再更新正式分镜并用显式清单合成。
8. 需要按旁白定片长时，先 `ntf run PROJECT --kind audio`，再 `ntf timing PROJECT --apply` 按实测校准并重新 plan。视频先行探索时，先选有效动作，再按真实配音安排剪辑窗口。读取所需媒体 Skill，按 `ntf ready PROJECT` 执行具体动作；公司通道调用传实际配置文件。
9. 使用 `ntf run PROJECT --action ID --config FILE --wait-seconds 20` 执行或查询；批次用kind/scene、submit-only/poll-only、max-new-actions与stop-on-error控制。地址与凭据来自环境变量、NoteToFilm 根目录 `.env` 或即时读取的 Codex 配置，`ntf routes` 显示每条路由的来源；临时换用另一份私有连接时加 `--connections-file`。只要旧动作仍可查询就继续它，不用新提交模拟轮询。
10. 每次取得实际文件后登记结果，审阅可用范围，再查看状态和下一步。同一项目写 state 的 CLI 串行执行；远端任务可通过批次提交后继续在服务端并行，只读媒体检查可并行。最终合成等待已采用的实际媒体。
11. 改变正式旁白、事实或屏幕文字时回到导演方法，保存主记录。分镜工作流重新 plan；独立候选路线更新正式分镜和合成清单，保留已有动作与素材。返工前先判断问题在哪一层（因果缺失改材料或文案，画面任务不清改分镜，人物道具漂移改参考，动作穿帮改动作范围或素材，转场不顺先看前后主体与方向，节奏拖沓删重复），direct 的常见做法里有完整的诊断表；只重做实际受影响的部分。

## 完成

成片按 compose Skill 的交付检查核查规格、事件连续性、字幕与声音。后处理后用 `ntf preview PROJECT --video FINAL_FILE --output DIR` 明确导出最终文件。按用户要求在材料、分镜、素材或 MP4 完成后结束，给出实际路径与未完成项。只有模型任务 ID 或提示词时，描述为已提交或已设计。

沿用用户对当前任务已有的次数、费用和通道授权；超出范围或需要新的业务取舍时再确认。用过付费通道时，用 `ntf status PROJECT --usage` 按模型汇总已受理、拒绝、未发送和未知的次数，列出生成素材数、源片总时长及直接进入成片的素材数。按通道计费方式估算花费，并注明账号用量的核对状态。连续失败时保留成功素材，按具体错误停止或调整该方向，避免把整批重跑当作恢复。

当前协议尚未配置时，继续完成不依赖该通道的内容、已知媒体和计划，指出缺少的具体连接信息。不要擅自切到官方接口、其他模型或另一家服务。
