# 依赖、恢复与修改

图像通常依赖画面要求；配音依赖旁白和声音；图生视频依赖实际选定图片；需要精确对应旁白的动作先使用真实音频时长；合成依赖采用素材与实际时间。

把每项操作写为当前项目的具体动作和直接 `needs`，不要创建通用条件语言。普通模型请求不依赖全片每一个字段，只有实际相关输入变化才需要重做。

配音时长变化不直接等于视频失效。先看现有片段是否仍适合新的合成安排。画面从“上升”改成“下降”则需要语义判断相关箭头和动作。

提交后已得到远端 ID 时继续查询原动作；不确定提交是否成功时，不自动再次发送付费请求。`--retry` 表示明确的新尝试；`--force --action ID` 表示明确重做已经完成的动作。它们不是轮询选项。

已有任务使用提交时的通道与协议快照继续，不因为当前配置换了模型就查询另一个服务。新配置用于新的请求或明确重做。只有取得文件并登记后才算素材完成。

改变项目默认值后查看status中的plan_current和stale_action_ids，重新plan再启动受影响的新动作。不要通过重复run绕过stale_plan；已有远端任务使用poll-only按原请求和通道快照恢复，取回的旧结果不冒充新参数的生成结果。

分镜驱动的正式工作流与独立候选生成可以衔接。`generate` 添加的是具体候选动作；保留其 ID 和素材，用显式合成清单选择有效片段。改正式文案后同步配音、字幕与清单，不为套用固定流程重新提交已有候选。需要回到自动 plan 时先核对将产生的动作和已有采用关系。

同一项目的 `generate`、`run`、`select`、`storyboard`、`plan`、`compose` 等写状态命令串行运行。要缩短远端等待，先用 `--submit-only` 提交一批，再用 `--poll-only` 取回；每次调用仍串行。项目文件的互斥与远端模型并发是两回事。

素材版本、正式旁白、后期图解、合成清单和最终成片分别记录采用关系。重排、改字或响度处理可复用已有素材，不因此重复付费生成。
